# ADR-009 — Autenticación y autorización en el API gateway

**Estado:** Aceptada  ·  **Contexto:** Portal de autoservicio de la fuerza de ventas

## Decisión
La autenticación (CTRL-001) y la autorización por recurso (CTRL-002, una consultora solo ve lo suyo) las aplica el API gateway antes de que la petición llegue al servicio, según el esquema SEC-SCHEME-xxx que declara cada endpoint y los datos del token (ADR-003). El servicio recibe solo peticiones autenticadas y autorizadas: sus handlers no validan el token ni la identidad de quien llama, y trabajan con los identificadores que llegan en la ruta, la consulta o el cuerpo. El registro de acceso a datos personales (CTRL-006) también lo hace el gateway. GATE-SEC-4 se verifica con las pruebas del gateway, no con las del servicio.

## Consecuencias positivas
Una sola implementación de la seguridad de acceso para todos los servicios; los handlers se mantienen pequeños y verificables.

## Consecuencias negativas / riesgos
El servicio confía en el gateway: no debe exponerse fuera de él. Un handler que fija en el código un identificador de consultora o de usuario rompe el modelo y es un defecto.
